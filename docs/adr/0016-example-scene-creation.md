# 0016: Example scene creation and Active Scene Setup

The package offers two setup paths. Active Scene Setup (`Editor/GamingCouchActiveSceneSetup.cs`) applies safe, non-destructive setup to the scene the user already has open — wiring its `GamingCouch` object, making it the first enabled Build Settings scene, and creating or reusing the example Game listener and player prefab references. Create New Example Scene (`Editor/GamingCouchExampleSceneCreation.cs`, reachable from the `GamingCouch/Create New Example Scene` menu and the Start Screen action) saves any modified open scene, opens a fresh scene with the default camera and light, saves it under `Assets/GamingCouch/GCExample/` with a unique name so existing example scenes are kept (the user is informed before a new one is added alongside them), runs Active Scene Setup on it, and opens the Start Screen; it deliberately does not promote the new scene to the first enabled Build Settings scene, so creating an example never silently changes which scene a build boots into — that stays an opt-in through the existing "Set up missing pieces" action. Example Assets (`GCGameExample.cs`, `GCPlayerExample.cs`, `GCPlayerExample.prefab` under `Assets/GamingCouch/GCExample`) are still generated as editable project files that are never overwritten and carry a header inviting users to move and rename them into their own project. This supersedes the earlier decision to ship no example-scene creation route: a one-click new scene lowers first-run friction, while unique naming, the no-overwrite rule, and the non-invasive Build Settings behavior preserve the properties that motivated the earlier decision (assets the user owns and can grow into their game, no throwaway package-owned scene, and no surprise build changes). Legacy generated-prefab compatibility checks remain only to guard old project assets.
