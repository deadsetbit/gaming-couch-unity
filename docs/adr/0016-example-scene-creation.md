# 0016: Example scene creation and Active Scene Setup

The package offers two setup paths. Active Scene Setup (`Editor/GamingCouchActiveSceneSetup.cs`) applies safe, non-destructive setup to the scene the user already has open — wiring its `GamingCouch` object, making it the first enabled Build Settings scene, creating or reusing the example Game listener and player prefab references, and selecting a 16:9 Game View when that is safe — it only ever selects an **existing** 16:9 entry from the Game View's size list, never creates, edits, or reorders sizes, and does nothing when no such entry exists or Unity's internal selected-size API is unavailable (`EnsureGameView16By9IfSafe` → `GamingCouchGameViewAspect.SelectExisting16By9Size`). The Game View selection is deliberately **both** automatic here and an opt-in Start Screen checklist action ("Game View uses 16:9 preview" → "Select 16:9", `GCStartScreenReadinessActionId.Select16By9GameView`), which is the confusing part of this design: both entry points call the same `SelectExisting16By9Size`, so the checklist button is a retry of the automatic pass rather than different behavior, and when the safety conditions do not hold neither acts and the checklist simply reports the aspect as not 16:9. Create New Example Scene (`Editor/GamingCouchExampleSceneCreation.cs`, reachable from the `GamingCouch/Create New Example Scene` menu and the Start Screen action) saves any modified open scene, opens a fresh scene with the default camera and light, saves it under `Assets/GamingCouch/GCExample/` with a unique name so existing example scenes are kept (the user is informed before a new one is added alongside them), runs Active Scene Setup on it, adds an on-screen Game View guidance label plus a clickable console log pointing at the generated example files (the Game View is otherwise empty because players only spawn at runtime), and opens the Start Screen; it deliberately does not promote the new scene to the first enabled Build Settings scene, so creating an example never silently changes which scene a build boots into — that stays an opt-in through the existing "Set up missing pieces" action. Example Assets (`GCExampleGame.cs`, `GCExamplePlayer.cs`, `GCExamplePlayer.prefab` under `Assets/GamingCouch/GCExample`) are still generated as editable project files that are never overwritten and carry a header inviting users to move and rename them into their own project. This supersedes the earlier decision to ship no example-scene creation route: a one-click new scene lowers first-run friction, while unique naming, the no-overwrite rule, and the non-invasive Build Settings behavior preserve the properties that motivated the earlier decision (assets the user owns and can grow into their game, no throwaway package-owned scene, and no surprise build changes). Legacy generated-prefab compatibility checks remain only to guard old project assets.
