# 0011: Runtime carries no JSON library dependency

Local Play Contract development relies on root `gc.dev.json`/`gc.platform.json` files parsed with Newtonsoft, but shipping that dependency in the Runtime assembly would drag JSON parsing into every player/WebGL build. We decided all Newtonsoft/JObject parsing, writing, and validation lives in the Editor assembly, exposed to Runtime only through the `IGCLocalPlaySessionProvider` seam (declared in `Runtime/Dev/GCLocalPlaySession.cs`, itself fully `#if UNITY_EDITOR`, implemented by `GCDevJsonLocalPlaySessionProvider` in `Editor/GCDevJsonLocalPlaySessionProvider.cs`), so Runtime consumes only neutral capture/preflight results (`GCSetupOptions`, `GCPlayOptions`, `GCSeatIdentity`, issue lists). Consequently `Runtime/dsb.gamingcouch.runtime.asmdef` references nothing, only the Editor asmdef references `Unity.Newtonsoft.Json`, and player builds carry no JSON library dependency (Runtime uses only Unity's built-in `JsonUtility`); any future Runtime JSON-library need must add its own deliberate dependency rather than leak the editor seam.
