# 0012: Defer cross-engine code extraction until a second engine adapter exists

Only one engine adapter (Unity) exists today; a Godot adapter is hypothetical, so extracting shared cross-engine code now would create a speculative seam with no real second consumer to shape it. We decided not to extract any shared implementation until a second engine adapter actually exists — portability is guaranteed at the contract level instead, by keeping the Local Play Contract stable and by the portable Contract Fixture corpus (`ContractFixtures/LocalPlay`, consumed by `Tests/Editor/GCDevJsonContractFixtureTests.cs`). A second engine therefore starts by implementing the Local Play Contract and passing the shared Contract Fixtures, not by importing Unity internals (see roadmap item 9 in `docs/architecture/gamingcouch-unity-architecture-improvement-roadmap.md`).
