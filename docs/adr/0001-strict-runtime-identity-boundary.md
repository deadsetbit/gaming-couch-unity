# 0001: Strict runtime identity boundary — games see only playerIndex

Hosted play payloads used to carry platform player IDs and player names into Unity game code, which leaked player-owned identity and invited games to key logic off platform identifiers. We decided that games address participants exclusively by a dense, zero-based `playerIndex` (`GCPlayer.Index`): `GCPlayOptions.CreateFromJSON` hard-rejects any `players[]` entry carrying `playerId` or `name` and enforces dense, duplicate-free indices with no legacy fallback, while removed identity APIs such as `GCPlayer.Id` and `GCPlayer.PlayerName` are marked `[Obsolete(..., true)]` so they fail at compile time. This is a deliberate one-way privacy and fairness boundary — platform identity stays platform-owned, and hosting layers (the hosted SDK/DevApp, per the cross-repo runtime contract) must translate to index-based payloads upstream rather than the package tolerating both shapes.
