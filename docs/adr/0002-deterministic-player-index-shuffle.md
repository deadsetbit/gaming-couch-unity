# 0002: Deterministic player index shuffle via FNV-1a hash-sort

Player indices must be shuffled each run (so `playerIndex: 0` grants no persistent advantage and games cannot rely on roster order) while producing identical assignments in both the Unity package and the hosted SDK/DevApp side of the cross-repo runtime contract, without shared code. We decided to assign indices by hash-sorting participants: each participant's stable key is hashed as UTF-8 `"{seed}:{stableKey}"` with FNV-1a 32-bit (offset basis `2166136261`, prime `16777619`, unsigned 32-bit wraparound), sorted ascending by unsigned hash with captured roster order as tie-break, and indices assigned densely from 0 — as implemented in `GCPlayerIndexMapping.Create` (`Runtime/GCPlayerIndexMapping.cs`) using the per-run seed from `GCPlayOptions.seed`. Hash-sort was chosen over a seeded PRNG shuffle because it is trivially reproducible across C# (`unchecked uint`) and TypeScript (`Math.imul(..., 0x01000193) >>> 0`) without agreeing on a PRNG algorithm; the algorithm is a bit-exact cross-language contract and must only be changed together with the shared cross-language fixtures (C# values pinned in `Tests/Editor/GCPlayerIndexMappingTests.cs`).
