# 0010: Root gc.dev.json is the canonical editor local-play settings source

Editor local-play settings used to live as serialized inspector fields (`gameModeId`, `playerData`, `numberOfPlayers`, `randomizePlayerIds`) on the `GamingCouch` component, which the DevApp could neither read nor edit; per the cross-repo contract the DevApp owns those files at the project root, so both sides needed one shared source of truth. We decided the root `gc.dev.json` is the only source Unity reads and writes for editor play settings — `devVersion: 2`, one `entryKey`, a `seed` of `"random"` or a fixed string integer, and exactly eight seats with a fixed source-slot color map (1: blue, 2: red, 3: green, 4: yellow, 5: purple, 6: pink, 7: cyan, 8: brown) — while the old serialized fields stay `[SerializeField, HideInInspector]` solely so old scenes deserialize, with no migration and no fallback. Unity never creates, bootstraps, or repairs `gc.dev.json` or `gc.platform.json` (a missing `gc.dev.json` is an error, `MissingFile`; a missing `gc.platform.json` is a warning, `MissingPlatformDataFile`, with fallback platform metadata), because file ownership belongs to the DevApp side of the contract; Unity only round-trips the canonical fields (`devVersion`, `entryKey`, `seed`, `seats`) through a `JObject` so unrelated top-level fields written by other tools are preserved.
