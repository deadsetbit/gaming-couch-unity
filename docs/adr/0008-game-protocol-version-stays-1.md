# 0008: gameProtocolVersion stays 1

The strict-current runtime boundary, the `gc.runtime-info.json` sidecar, upload validation, and build diagnostics all landed without changing the protocol version: `gameProtocolVersion` remains `1` (`Runtime/Resources/GamingCouchRuntimeInfo.json`). We decided that changes the hosting side can adapter-translate — per the cross-repo runtime contract, the hosted client/SDK translates legacy payloads into current shapes before Unity is invoked — never bump it, and neither do sidecar/upload-validation, diagnostics, package-metadata, or editor-tooling changes; a bump is reserved for a required platform/game contract change that games and SDK adapters cannot translate, and remains a release-owner decision weighed on rollout risk and adapter compatibility. Version concerns that are not the game contract get their own fields instead: `gc.unity-build-info.json` carries its own `schemaVersion`, and any future `gc.runtime-info.json` file-schema change must add a separate sidecar schema field rather than reuse `gameProtocolVersion`.
