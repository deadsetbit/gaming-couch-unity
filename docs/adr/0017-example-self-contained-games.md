# 0017: Example split into swappable self-contained games, generated from canonical source

The generated example stops being a single `GCGameExample` MonoBehaviour and becomes **two self-contained, swappable game scripts** that share one scene, so a developer can either start from a barebones template or study a full game with no extra plumbing layer between them and the platform. Each script *is* the `listener` the platform talks to: it implements the convention-based `GamingCouchSetup(GCSetupOptions)` / `GamingCouchPlay(GCPlayOptions)` methods that `GamingCouch` invokes by `SendMessage` (`Runtime/GamingCouch.cs:305,441`) directly — no adapter, no shared base class, no forwarding component — deliberately keeping the whole platform contract visible in one readable file, which serves a learn-by-example template better than the separation-of-concerns that belongs to the future authoring-ergonomics API (B001). `GCExampleTemplate` is the barebones starting point: it spawns the stock `GCPlayer` capsule, drives `SetupGameVersus`/`SetupDone`/`GameOver` so the platform loop completes, and `Debug.Log`s each lifecycle step — the absolute minimum a developer copies and grows into their own game. `GCExampleGame` is the full reference of the same shape: a small playable loop (scoring, rounds, per-player input) using a custom `GCExamplePlayer` (renamed from `GCPlayerExample`) with real visuals and HUD. All example types share a `GCExample…` prefix to stay clearly distinct from the package's built-in `GCGame` / `GCGameVersus` game-mode objects (`Runtime/Game/`), which are a different concept. The two setup entry points form an additive, single-scene flow: "Create New Example Scene" resets to one clean `GCExampleScene` wired to `GCExampleTemplate` and the stock player — superseding ADR 0016's create-a-scene-alongside behavior with the idempotent reset already shipped in the tooling (`Editor/GamingCouchExampleSceneCreation.cs`), which moves previous example scenes and leftover blocking folders to the Trash (recoverable, bar the one empty-stray-folder exception in Consequences) — while a new "Wire example game" action upgrades that same scene in place, swapping the wired component to `GCExampleGame` and the player prefab to `GCExamplePlayer`, never as a second scene. Generation stops splicing string literals: each script's canonical source lives as real, compiled code in an in-repo, `UNITY_INCLUDE_TESTS`-gated, `autoReferenced:false` assembly (modeled on `Tests/Fixtures/GamingCouch.Tests.Fixtures`) that compiles against the real runtime in the editor and CI — the anti-drift compile guarantee that nothing provided before — but never compiles into a consumer player build; the generator copies each master and rewrites names into the user's project. The example ships as generated, editable Example Assets with no new package public API — reversible before B001 decides the authoring API — and `gameProtocolVersion` stays 1 (ADR 0008): this reorganizes the example, not the platform↔game wire contract.

## Consequences

- **Never-overwrite and no-surprise-Build-Settings are preserved (ADR 0016).** Example scripts and the player prefab are reused, never overwritten; promoting the example scene to the first enabled Build Settings scene stays opt-in through the "Set up missing pieces" (Active Scene Setup) action. The reset action moves replaced assets to the Trash (recoverable) rather than deleting them, with one narrow exception: a folder blocking a generated asset path that Unity never imported as an asset folder cannot be sent to the Trash, so if it is **provably empty** it is removed outright together with its `.meta` — the stray `".cs"`-named-folder case (`TryRemoveBlockingAssetFolder`, `Editor/GamingCouchActiveSceneSetup.cs`). A non-empty folder in that state is refused with a remove-it-manually message instead, and a *file* at such a path is never touched, so no user content can be lost either way.
- **Two self-contained scripts means the platform-contract boilerplate appears in both.** That duplication is intentional: each file is a complete, runnable reference, which serves the template/learning goal better than sharing a hidden base class. Factoring the shared shape into a reusable adapter/contract is deferred to the authoring-ergonomics work (B001), not baked into the example.
- **Master types carry a `Source` suffix, stripped on copy.** The generator's `FindTypeByName` guard (`Editor/GamingCouchActiveSceneSetup.cs`) matches by simple type name across every loaded assembly and refuses generation if a master shares a name with the generated output; distinct `…Source` names avoid the collision (the same guard forced the 2026-07-11 test-fixture renames). A golden test asserts each generated file equals its master after name rewrite, replacing the brittle hardcoded substring assertions.
- **No injectable platform facade.** Game logic reads `GamingCouch.Instance` directly (simplest generated code); correctness is guarded by the compile guarantee, the golden generation test, and a PlayMode smoke test that drives setup → play → input → game-over.
- **Docs codify two honest tiers.** The template is the wiring demo; the example game is a small playable loop — resolving the README ("a complete, working game") vs CONTEXT ("a wiring demo, not a full sample game") contradiction. Advances backlog B004.
